# 창원경일고 학생부 성적분석 시스템 — v1.4.0

학생의 과목별 성적 원자료(과목·단위수·등급)를 한 번 입력하면, 여기서 파생된 계산 결과를
1·2·3학년에 걸쳐 계속 활용할 수 있도록 설계한 학생부 성적분석 시스템의 Phase 1~2 MVP입니다.

이 문서는 마스터 프롬프트 39조 "README에 반드시 포함할 것" 항목을 기준으로 작성했습니다.


> **v1.4.0 핵심 수정사항**: 텍스트형 학교생활기록부 PDF를 일반 문장처럼 파싱하지 않고 `교과학습발달상황` 표의 실제 x/y 좌표를 직접 읽는 전용 파서를 추가했습니다. 봉사활동 날짜가 과목으로 들어오는 문제를 구조적으로 차단하고, 여러 과목 행에 걸쳐 병합된 `학기` 셀의 중앙 좌표를 기준으로 1·2학기를 분리합니다. 실제 22쪽 학교생활기록부 샘플을 외부 검증 데이터로 사용해 1-1/1-2/2-1/2-2/3-1 다섯 학기의 등급 산출과목이 모두 분리되는 것을 확인했습니다(검증용 원본 PDF는 저장소에 포함하지 않음). 프로그램명은 `학생부 성적분석 시스템`으로 정리했고, 자동추출 검토표에서 `평가방식`은 `등급/성취평가`로 표시합니다.
> **v1.2.0 주요 변경사항**: 1·2·3학년 공용 화면으로 전환하고 현재 학년을 선택하면 코호트에 맞춰 5등급제/9등급제를 자동 판정합니다. 학생부 PDF·성적표 이미지는 여러 파일을 한 번에 선택·드롭할 수 있고, 캡처 이미지는 Ctrl+V를 여러 번 해도 검토 후보가 누적됩니다. 또한 사용자가 제공한 `내신 목표 등급 설정(1).xlsm`의 `VLOOKUP(I2,'9등급 환산'!A2:B73,2,1)`과 환산표를 그대로 옮겨 5등급제의 모든 주요 평균 결과에 9등급 참고 환산값을 함께 표시합니다.

---

## 1. 프로젝트 목적

기존 두 개의 Excel 파일(`3학년 수시 상담.xlsx`, `내신 목표 등급 설정.xlsm`)의 계산 로직(특히
단위수 가중평균과 목표등급 역산 구조)을 계승하고, 이번 v1.2.0부터는 사용자가 제공한 Excel의
`9등급 환산` 시트와 근사 VLOOKUP 함수를 상담용 5→9등급 참고 환산표로 명시적으로 반영했습니다. 이를 각 학년용 개별 파일이
아니라 **하나의 공통 데이터 구조 + 계산엔진** 위에서 동작하는 웹 애플리케이션으로 재설계했습니다.

핵심 원칙:
- 학생 성적의 최소 단위는 "과목 1개 = record 1개" (교과군 평균을 직접 입력하지 않음)
- 석차등급(rankGrade)과 성취평가(A~E)는 절대 하나의 숫자로 섞지 않음
- 5등급제와 9등급제 성적도 절대 하나의 공식 평균으로 섞지 않음 (섞여 있으면 평균 자체를 계산하지 않고 값 없음으로 표시)
- 대학명·계산규칙을 코드에 하드코딩하지 않고 데이터로 표현할 수 있는 구조를 열어둠
- 학생 개인정보는 서버로 전송하지 않음 (정적 웹, 로컬 저장 + JSON 백업)
- 편집할 수 없는 데이터 유형(P/F 등)이라도 자동으로 다른 유형으로 바꾸지 않고 원본 그대로 보존

## 2. 이번 MVP의 구현 범위

**구현됨 (Phase 1~2 + 자동입력/학기분석 확장)**
- 학생부 PDF 자동 읽기: PDF.js 기반 텍스트 추출 우선, 텍스트가 없는 스캔 PDF는 OCR로 자동 전환
- 성적표 이미지 다중 업로드·다중 드래그앤드롭·Ctrl+V 반복 붙여넣기 OCR: Tesseract.js를 브라우저에서 사용, 여러 사진의 검토 후보를 누적
- 자동 추출 검토표: 학년·학기·교과군·과목명·단위수·등급/성취도를 수정한 뒤 확정 반영
- 수동 입력에도 이수 학기 선택을 추가해 1-1, 1-2, 2-1, 2-2, 3-1 분석 가능
- 공통 조합 자동 계산: 국영수 / 국영수사 / 국영수과 / 국영수사과 / 전교과
- 전체 값은 학기 평균의 단순평균이 아니라 5개 학기의 모든 과목을 다시 합쳐 단위수 가중평균으로 계산
- 현재 학년(1/2/3)을 선택하면 입학연도 기준으로 5등급제/9등급제를 자동 판정
- 5등급제 평균은 제공 Excel의 근사 VLOOKUP 환산표로 9등급 참고값을 자동 병기(원등급은 그대로 보존)
- 공통 데이터 스키마 v1.0 (`src/models/academic.ts`)
- 단위수 가중평균 계산엔진 (`src/engines/gradeEngine.ts`)
- 목표등급 역산 + 시나리오 엔진 (`src/engines/targetEngine.ts`)
- 1·2·3학년 통합 상담 UI: 교과군별 단위수·등급 입력(항목별 등급체계 지정 가능), 목표등급 역산,
  모의고사 기록(등급+백분위+한국사), 대학 조사표(학년별 비율·연도별 수능최저·연도자료 수정/삭제
  포함), 상담메모
- JSON 저장/불러오기 (장기 백업, 학년 간 데이터 이어쓰기), 마이그레이션 후 런타임 정규화로
  손상·불완전 파일도 안전하게 로드
- 익명 저장 옵션 — 실제로 JSON·Excel 파일 내용에서 이름·학번을 제거
- IndexedDB 자동저장 (현재 기기 입력 복구용, 앱 시작 시 1회만 복구하며 재귀 호출 없음)
- 스키마 마이그레이션 시스템 (구버전 JSON 자동 변환, `v0.9 → v1.0` 실동작 예시 포함)
- 상담용 Excel(.xlsx) 자동 생성 (ExcelJS, 5개 시트, 가중평균은 숫자 셀로 저장, 모의고사·전체
  상담메모 포함)
- 단위 테스트 정의 95건 (계산엔진·목표역산·마이그레이션·정규화·익명화·JSON 왕복·Excel 출력·자동저장
  재귀 방지 회귀테스트·원본 Excel 예시 시트 수치 재현)

**구현하지 않음 (향후 Phase 3+)** — 구조는 열어두었으나 이번에 만들지 않은 것:
- 학교 편제표 기반 과목마스터 자동완성(현재는 PDF/이미지 자동추출 및 수동 과목명 입력으로 운영)
- 전국 대학 3개년 입결 DB, 대학별 반영규칙 DB (`src/models/university.ts`에 구조만 정의) —
  현재 화면의 "국수영사과" 등 조합은 **아직 특정 대학의 확정 규칙이 아닌 참고용 조합**입니다
- 본교 3개년 지원·합불 데이터 연동, "선배 사례 매칭"
- 교사용 전체 학생 대시보드
- Google Drive 자동 백업
- 수능최저 자동 판정 (모의고사·대학별 수능최저 기록은 저장되지만 자동 충족 여부 판정은 미구현)

**Phase 3 착수 전 반드시 설계할 것 (3차 검수 지적, 현재 배포 차단 사유는 아님)**: 지금은
`precise`(정밀입력) 레코드와 `quickAggregate`(빠른입력) 레코드를 둘 다 그대로 계산에
합산합니다. 1·2학년 정밀입력 UI가 없는 지금은 문제가 되지 않지만, 이후 정밀입력을 도입하면
"1·2학년 정밀자료로 이미 잡힌 국어 40단위"와 "3학년 빠른모드에서 학생이 다시 입력한 누적
국어 55단위"가 동일한 기간을 중복 대표해 95단위로 이중 계산될 위험이 있습니다. Phase 3 착수
전에 각 레코드(특히 quickAggregate)가 어떤 학업 기간을 대표하는지 범위(coverage)를 명시하는
필드를 설계해야 합니다.

## 3. 설치 방법

**요구 사양**: Node.js `^20.19.0` 또는 `>=22.12.0` (핵심 의존성인 Vite 8이 정확히 이 범위를
요구합니다 — `node_modules/vite/package.json`의 `engines` 필드 기준). `package.json`의
`engines` 필드에 동일하게 명시되어 있습니다. 개발 의존성인 jsdom은 더 넓은 버전(26.x, Node
≥18)을 지원하도록 낮춰뒀지만, 실제로 앱을 빌드·실행하려면 Vite의 요구 버전을 따라야 합니다.
이 요구사항은 테스트/빌드 도구에만 해당하고, 실제 배포되는 웹앱 자체는 Node에 의존하지 않는
순수 정적 사이트입니다.

```bash
npm install
```

타입 검사만 별도로 실행하려면:

```bash
npm run typecheck
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 접속.

## 5. 빌드 방법

```bash
npm run build
```

`dist/` 폴더에 정적 파일이 생성됩니다. `vite.config.ts`에서 `base: "./"`로 고정되어 있어
자산 경로가 항상 상대경로(`./assets/...`)로 생성되며, 저장소 하위 경로(GitHub Pages 등)나
임의의 서버 디렉터리에 배포해도 경로가 깨지지 않습니다(직접 테스트로 확인: 루트 배포와
`/repo-name/` 하위경로 배포 둘 다 정상 동작).

**중요 — `file://`로 직접 여는 것에 대해**: `index.html`을 더블클릭해 `file://` 프로토콜로
직접 열면, 상대경로 여부와 무관하게 **대부분의 브라우저(특히 Chrome 계열)가 ES 모듈 스크립트를
CORS 정책상 차단**하여 화면이 비어 있을 수 있습니다. 이는 이 프로젝트만의 문제가 아니라
`<script type="module">`을 쓰는 모든 정적 웹앱에 공통된 브라우저 제약입니다. 따라서:
- **로컬에서 빌드 결과물을 확인할 때는 반드시 `npm run preview`(Vite 내장 서버) 또는
  `python3 -m http.server` 같은 간단한 정적 HTTP 서버를 통해 열어야 합니다.**
- 실제 배포는 GitHub Pages 등 HTTP(S) 서버를 사용합니다.

ExcelJS는 "Excel 상담자료 생성" 버튼을 누를 때만 별도 청크로 로드되도록 코드 분할되어 있어
초기 로딩 속도에는 영향을 주지 않습니다.

## 6. GitHub Pages 배포 방법

**자동 배포 (권장)**: 이 저장소에는 `.github/workflows/deploy.yml`이 포함되어 있습니다.
소스 폴더 전체를 GitHub 저장소의 `main` 브랜치에 그대로 올리기만 하면, push할 때마다
GitHub Actions가 자동으로 `npm ci` → 타입체크 → 테스트 → `npm run build` → Pages 배포까지
수행합니다. 별도로 로컬에서 빌드하거나 `dist`를 직접 올릴 필요가 없습니다.
1. 저장소 Settings → Pages → Source를 "GitHub Actions"로 지정
2. 소스 코드를 push
3. Actions 탭에서 배포 진행 상황 확인, 완료 후 안내되는 URL로 접속

**수동 배포**: 워크플로를 쓰지 않으려면 다음과 같이 직접 진행합니다.
1. `npm run build`로 `dist/` 생성
2. 저장소에 `gh-pages` 브랜치를 만들거나, `dist` 폴더 내용만 별도로 올림
3. `base: "./"` 설정 덕분에 저장소가 `https://{user}.github.io/{repo}/` 형태의 하위 경로에
   배포되어도 별도 설정 변경 없이 정상 동작합니다(직접 검증 완료)
4. Settings → Pages에서 배포 브랜치/폴더 지정

## 7. 학생 사용 방법

1. 사이트 접속 → 이름(선택)과 **현재 학년(1/2/3)**을 선택. 이름·학번을 파일에 남기고 싶지 않다면 "익명 저장" 체크
2. **권장: 00. 학생부·성적표 자동 불러오기**에서 학생부 PDF 또는 성적표 이미지를 여러 개 올리거나 한꺼번에 드롭합니다. 캡처 이미지는 Ctrl+V를 여러 번 붙여넣을 수 있으며 기존 검토 후보가 누적됩니다. 자동 추출 후 검토표에서 학년·학기·과목·단위수·등급을 확인하고 [검토한 성적 반영]을 누릅니다.
3. 직접 입력이 필요한 경우 "01. 성적 입력"에서 교과군별 [+ 입력 추가]를 누르고 이수학기·과목명·단위수·등급을 입력
   - 각 항목마다 등급체계(5등급제/9등급제)를 개별 지정할 수 있습니다. 서로 다른 등급체계가
     섞이면 평균을 계산하지 않고 경고를 표시합니다(임의로 환산해 섞지 않는다는 원칙)
   - 진로선택 등 석차등급이 아닌 과목은 유형을 "성취"로 바꾸고 A~E 선택 (평균에는 반영되지
     않고 별도로 표시됩니다)
4. 화면 아래 표에서 교과군별 가중평균과 국영수·국영수사·국영수과·국영수사과·전교과의 학기별/전체 가중평균을 확인. 5등급제이면 각 결과 옆에 **9등급 환산 참고값**이 함께 표시됩니다.
5. "02. 목표등급 역산"에서 앞으로 이수할 단위수와 목표 누적등급(이 수치 이하가 되도록)을
   입력해 필요한 평균 확인
6. "03. 모의고사 기록"에 회차별 등급·백분위·한국사를 입력하면 국+수+탐구1 백분위 합도 자동
   계산됩니다. "04. 대학 조사"에는 반영비율·반영교과·학년별 비율·수능최저와 함께, 알고 있는
   3개년 입결 정보를 직접 조사해 입력하세요(직접 조사는 탐구활동이자 의도된 설계입니다). 등록한
   대학·연도 자료는 언제든 카드 안에서 바로 수정하거나 연도별로 삭제할 수 있습니다
7. 하단 액션바에서 **[내 데이터 JSON 저장]**을 눌러 파일로 백업 (다음 학년에도 이 파일을
   불러오면 이어서 사용할 수 있습니다)
8. **[Excel 상담자료 생성]**으로 상담용 .xlsx 파일 다운로드

## 8. JSON 백업/복원 방법

- **저장**: 액션바의 [내 데이터 JSON 저장] → `{이름 또는 익명}_진학설계_{날짜}.json` 다운로드.
  익명 저장이 켜져 있으면 파일 내용(JSON 본문)에서도 실제로 이름·학번이 제거됩니다.
- **복원**: [JSON 불러오기] → 파일 선택 → 자동으로 현재 스키마 버전까지 변환된 뒤, 누락되거나
  손상된 필드는 안전한 기본값으로 보정되어 로드됩니다(런타임 정규화)
- 구버전 파일을 불러오면 자동 마이그레이션이 적용되고, 어떤 변환이 적용되었는지 토스트
  메시지로 안내합니다. 불러온 데이터는 즉시 자동저장에도 반영되어, 화면을 새로고침해도
  방금 불러온 값이 유지됩니다(과거 자동저장 데이터로 되돌아가지 않음)
- `samples/sample-current-v1.0.json` : 정상 동작 확인용 샘플
- `samples/sample-legacy-v0.9-for-migration-test.json` : 마이그레이션 동작 확인용 구버전 샘플
  (불러오기 시 `0.9 → 1.0` 변환이 실제로 적용되는 것을 확인할 수 있습니다)

**중요**: 학생 데이터는 이 기기(IndexedDB, 자동저장·복구용)와 다운로드한 JSON 파일에만
저장되며, 서버로 전송되지 않습니다. JSON 파일을 잃어버리면 데이터를 복구할 수 없으므로,
학기 말이나 주요 입력 후에는 꼭 JSON 저장을 권장하세요.

## 9. Excel 생성 방법

액션바의 [Excel 상담자료 생성] 클릭 → `{이름 또는 익명}_상담자료.xlsx` 다운로드. 아래 5개
시트가 생성됩니다.

| 시트 | 내용 |
|---|---|
| 01_상담요약 | 핵심 가중평균 원등급 + 9등급 환산 참고값, 교과군별 요약, 모의고사 기록, 지원 후보 목록, 등급체계 혼재 경고 |
| 02_성적원자료 | 입력한 모든 과목의 단위수·평가유형·등급·등급체계 + 9등급 환산 참고값 |
| 03_성적분석 | 교과군별 분석 + 국영수/국영수사/국영수과/국영수사과/전교과의 5개 학기 및 전체 단위수 가중평균, 각 원등급/9등급 환산 병기 |
| 04_대학조사 | 대학·학과·전형·학년별 비율 정보 및 연도별 입결·수능최저 조사 자료 |
| 05_상담메모 | 전체 상담메모 + 대학별 메모 취합 |

익명 저장이 켜져 있으면 Excel 파일 내용에서도 이름이 제거됩니다.

PC에서 실행해도 동작합니다).

## 12. 데이터 개인정보 원칙

- 학생 성적·개인정보는 **서버로 전송되지 않습니다.** 이 웹앱은 정적 사이트로 배포 가능하며,
  API 호출이나 원격 저장소로의 자동 전송을 포함하지 않습니다. 외부 CDN(웹폰트 등)에도
  의존하지 않도록 시스템 폰트만 사용합니다.
- 원자료는 IndexedDB(자동저장) + 학생이 직접 내려받는 JSON 파일에만 존재합니다.
- "익명으로 저장" 옵션을 켜면 JSON·Excel 파일 **내용 자체**에서 이름·학번이 제거됩니다
  (이전 버전에서는 파일명만 바뀌고 내용에는 이름이 남아있는 버그가 있었으나 수정되었습니다).
- 향후 본교 3개년 지원·합불 데이터를 연동할 경우, 개별 학생 원자료는 학생용 정적 웹에
  포함하지 않고 익명 집계자료만 제공해야 합니다(코드 미구현, 원칙만 문서화).

## Assumptions (구현 중 합리적으로 정한 기본값)

첨부 Excel 및 마스터 프롬프트에 명시되지 않아 개발 중 자체적으로 정한 사항:

1. **대학 반영교과 조합의 기본값**: 원본 3학년 Excel의 F24(국수영사과한)/F25(전교과) 대신,
   MVP에서는 대학명을 하드코딩하지 않는 원칙에 따라 "국수영사과", "국수영사과+한국사" 2가지
   범용 조합과, 고정 리스트로 필터링하지 않는 "전교과(전체 원자료 그대로)"를 기본 제공합니다.
   화면·Excel 모두 이 조합을 **"참고용"**으로 명시해 특정 대학의 확정 규칙처럼 보이지 않도록
   했습니다. 특정 대학별 반영교과 자동 매칭은 Phase 3의 대학규칙 DB 구축 이후 가능합니다.
2. **목표등급 시나리오 간격**: 다음 구간 평균 후보를 1.0부터 등급체계 최댓값 미만까지 0.3
   간격으로 생성하고, 등급체계 최댓값(5.0/9.0)은 간격과 무관하게 항상 마지막 행에 포함합니다
   (모든 값은 현재 데이터 기반 동적 계산이며, 간격 자체만 임의 설정값).
3. **9등급 환산표**: 원본 Excel의 73개 lookup 값은 출처가 확인되지 않아 이번 MVP에는
   포함하지 않았습니다(핵심 계산에서 완전히 제외). 출처가 확인되면 "참고용 환산" 기능으로
   별도 추가할 수 있도록 스키마의 `gradeScale` 필드가 5/9 등급제를 구분해 둡니다.
4. **성취도 A~E의 대학별 환산**: 대학규칙 DB가 없는 이번 MVP에서는 성취평가 과목을
   화면·Excel 모두에서 "참고 표시"로만 제공하고 숫자 환산을 하지 않습니다.
5. **과목 ID(courseId) 미사용**: 빠른 상담모드에서는 학교 편제 연동이 없어 `courseId`를
   비워둡니다. 정밀입력(Phase 3)에서 과목마스터 연동 시 채워지도록 필드만 마련해 두었습니다.
6. **익명 저장의 범위**: `profile.anonymized`가 true면 JSON·Excel 출력 시점에 `profile.name`,
   `profile.studentId`를 제거합니다. `gradeLevel` 등 비식별 정보는 상담 맥락상 유용하므로
   유지합니다.
7. **빠른모드의 학년·학기 값**: 빠른입력은 학기별로 구분해 입력받지 않는 교과군 단위 집계이므로,
   생성되는 `AcademicRecord`에는 `sourceMode: "quickAggregate"` 표시를 남겨 "실제 이수 시점이
   정밀하게 기록된 데이터가 아니라 집계값"임을 구분할 수 있게 했습니다. 정밀입력(Phase 3)에서
   생성되는 레코드는 `sourceMode: "precise"`(또는 미지정)로 구분됩니다.
8. **등급체계 혼재 처리**: 전역 "새 항목 기본 등급체계" 선택은 새로 추가하는 항목의 기본값에만
   적용되고, 이미 입력되었거나 JSON으로 불러온 항목의 등급체계를 소급 변경하지 않습니다. 따라서
   한 학생의 데이터 안에 5등급제·9등급제 항목이 섞여 있을 수 있으며, 이 경우 원칙에 따라
   가중평균을 계산하지 않고 경고를 표시합니다.
9. **빠른모드에서 편집 불가능한 유형(P/F 등)**: `evaluationType`이 `passFail`/`other`인
   레코드는 이 화면에서 만들거나 수정할 수 없지만, JSON으로 불러온 경우 삭제·변형 없이
   그대로 보존되어 저장·Excel 출력에 포함됩니다.
10. **목표등급 계산의 등급체계 판단**: 상단 "새 과목 입력 시 기본 등급체계" 선택값은 새 항목
    생성 시 기본값으로만 쓰이고, 목표등급 역산·시나리오 계산은 `getActiveGradeScale()`로
    실제 01번 성적 데이터에서 등급체계를 판단합니다. 데이터가 없거나 혼재되어 있으면 계산을
    거부합니다.
11. **엔진 레벨 값 검증**: 화면의 min/max 입력 속성은 사용자 편의일 뿐 신뢰하지 않습니다.
    JSON 불러오기 등으로 범위를 벗어난 값(예: 5등급제인데 8등급)이 들어와도 계산 엔진이
    최종적으로 걸러내고, 제외된 과목 수와 사유를 화면에 표시합니다(값을 몰래 삭제하지 않고
    원자료는 그대로 보존하되 계산에서만 제외).

   표시하면서도 계산엔진은 그대로 포함시켰습니다. `MAX_CREDITS_PER_RECORD` 상수를
   `gradeEngine.ts`에 두고 `utils/validation.ts`가 그 값을 가져다 쓰도록 통일했으며,
   계산엔진의 `isCalculableRankGradeCourse()`도 이 상한을 검사하도록 수정
2. **`getActiveGradeScale()`이 무효한 등급값까지 등급체계 판단에 포함시키던 문제**: 예를 들어
   9등급제인데 99등급처럼 애초에 평균 계산에서 제외될 이상값 하나 때문에, 나머지 정상적인
   5등급제 데이터까지 "혼재"로 오판해 목표등급 계산을 막아버릴 수 있었습니다.
   `isCalculableRankGradeCourse()`를 공용 함수로 export해 `getActiveGradeScale()`도 "실제로
   평균 계산에 포함되는 과목"과 완전히 동일한 기준으로 판단하도록 통일
3. **`package.json`의 Node 요구 버전이 실제 의존성(Vite)과 맞지 않던 문제**: `>=18`이라고
   되어 있었지만 Vite 8은 `^20.19.0 || >=22.12.0`을 요구합니다. `engines` 필드와 README를
   Vite의 실제 요구사항에 맞춰 수정하고, GitHub Actions의 Node 버전도 `22.12.0`으로 고정
   (재현성 향상)

## 12. PDF/OCR 개인정보 및 정확도

- 학생부 PDF와 이미지는 성적 추출을 위해 애플리케이션 서버로 업로드하지 않습니다.
- PDF.js/Tesseract.js 코드와 한글 OCR 모델은 CDN에서 다운로드될 수 있으므로 인터넷 연결이 필요합니다.
- OCR은 숫자·한글을 오인식할 수 있으므로 자동 추출 결과를 바로 확정하지 않고 검토표에서 확인하도록 설계했습니다.
- 실제 학생부 양식에 따라 파서 규칙을 추가 보정하면 정확도를 더 높일 수 있습니다.
